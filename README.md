## Projects

### 🛡️ 도메인 특화 에이전트의 위험 행동 통제를 위한 가드레일
`HCLT 2026` · [📂 상세 보기](./Research/AI Agent Guardrail)

**현장 문제** · 출처 신뢰도가 불균일하고 정치적으로 민감한 도메인에서 검색 에이전트가 검증되지 않은 주장을 사실처럼 전달하거나 부적절한 경로로 자료를 수집할 수 있습니다. 기존 가드레일은 프롬프트 인젝션 같은 범용 위험에 집중되어 있습니다.

**접근** · 도메인 위험 행동을 8개 범주로 정의하고, 입력단에 **계획 수립 → 검토 → 판정** 프로세스를 구축했습니다. 각 단계는 구조화된 JSON으로 판단 근거를 남겨 감사(audit)가 가능하도록 했습니다.

**발견** · 에이전트는 계획 단계에서 위험을 스스로 인식했지만 실행을 멈추지 않았습니다. 별도의 검토 단계를 둘 때에야 인식이 실제 차단으로 이어졌습니다. 반면 완곡한 표현의 위험 요청은 두 단계 모두 놓쳤습니다.

**도입 시사점** · AI 에이전트를 업무에 넣을 때는 모델의 판단력보다 **인식된 위험을 조치로 연결하는 구조**가 핵심이며, 모호한 요청에는 사용자 의도 확인 절차가 필요합니다.

`LLM Agent` `Guardrail` `Risk Taxonomy` `Auditability`

### 🎙️ 저자원 도메인 STT 적응과 도메인 가중 평가 지표
[📂 상세 보기](./Research/stt finetuning)

**현장 문제** · 표준어 중심으로 학습된 STT는 특수 도메인 어휘를 체계적으로 오인식합니다. 보안상 상용 API를 쓸 수 없고, 데이터와 컴퓨팅 자원도 제한적입니다.

**접근** · 오픈소스 Whisper large-v3에 LoRA를 적용해 소량 데이터(1h → 15h)로 적응시켰고, 도메인 어휘의 이질성에 따라 오류에 가중치를 주는 지표 **DW-WER**을 설계했습니다.

**결과** · 15시간 학습으로 WER 41.19% → 36.99%, CER 15.06% → 13.09%로 개선되었습니다. 그러나 구간별로 보면 가장 중요한 이질 어휘군은 5시간 지점 이후 오히려 악화되었습니다(paired bootstrap, p<0.05).

**도입 시사점** · "전체 정확도가 올랐다"는 보고만으로 배포를 결정하면 핵심 어휘의 실패를 놓칩니다. 도메인 기준의 **세분화된 검증 절차**를 도입 전에 설계해야 합니다.

`ASR` `Whisper` `LoRA` `On-premise` `Evaluation Design`
