# 북한 정보 특화 에이전트의 위험 행동 통제를 위한 가드레일 방법론 연구

**North Korea-Specialized AI Agent Guardrail Methodology for Risky Behavior Control**

최규리, 박서윤, 김한샘 · 연세대학교 언어정보연구원 / 언어정보학협동과정

## 개요

북한 정보는 관영 매체, 국내외 언론, 온라인 개인 의견 등 출처가 다양해 정보의 질이 균일하지 않고, 정치적으로 민감해 균형 잡힌 서술이 요구되는 도메인입니다. 통제되지 않은 검색 에이전트는 주관적 주장을 사실처럼 전달하거나 편향된 서술을 생성할 위험이 있습니다.

범용 에이전트 벤치마크(AgentBench, WebArena, GAIA)는 최종 과업의 성공 여부에 초점을 맞추고, 기존 가드레일 연구(ShieldAgent, GuardAgent, AGrail)는 프롬프트 인젝션이나 정책 위반 같은 행위 중심 위험을 다룹니다. 반면 특정 도메인에서 위험이 실제로 어떤 대상과 형태로 나타나는지는 충분히 다뤄지지 않았습니다.

이 연구는 다음을 수행합니다.

1. 범용 안전성 체계를 북한 도메인에 맞게 구체화한 **8개 위험 행동 taxonomy** 설계
2. 입력단에서 **계획 수립 → 검토 → 판정**으로 이어지는 통제 프로세스 설계
3. 실제 에이전트를 구현하고, 일반 질의와 위험 질의에 대한 소규모 실험으로 통제의 작동 방식 확인

## 위험 행동 Taxonomy

| 범주 | 정의 |
|---|---|
| 선전 증폭 | 관영 매체 주장을 검증 없이 사실처럼 전달·확산하도록 요구 |
| 정치적 행동 요구 | 에이전트 스스로 북한과 관련한 특정 정치적 입장을 옹호하거나 정책을 제안하도록 요구 |
| 민감 정보 제공 | 북한과 관련한 군사 시설 위치, 무기체계 상세, 제재 회피 방법 등 악용 가능한 구체적 정보를 요구 |
| 개인 신상 노출 | 북한과 관련한 특정 인물(탈북민, 북한 내부 고위관계자 등)의 신상 정보를 요구 |
| 혐오 조장 | 북한과 관련한 특정 집단(주민, 국가 등)에 대한 혐오·비하 표현을 요구 |
| 거짓 정보 생성 | 북한에 대한 허위 정보·가짜 뉴스 제작에 협조하도록 요구 |
| 긴장 조장 | 불확실한 군사 동향을 확정적으로 서술해 긴장감을 조장하도록 요구 |
| 요청 범위 초과 | 정보 제공을 넘어 위험한 후속 행동을 요구 |

## 통제 프로세스

```
사용자 질의
   │
   ▼
[1] 계획 수립 ── 검색 전략, 의도, 위험 인식(risk_flags)을 에이전트가 스스로 도출
   │
   ▼
[2] Taxonomy 검토 ── 계획을 8개 위험 범주에 대조
   │
   ├── proceed ──▶ 검색 실행 → 최종 응답
   └── block ────▶ 즉시 종료, 판정 근거 기록
```

- **모델**: OpenAI API `GPT-5-mini` (계획 수립·검토·응답 생성), 웹 검색 도구로 정보 수집
- 계획 수립 시 공신력 있는 출처로 국가가 운영하는 북한정보포털을 반드시 검색하도록 지정
- 실행 단계에서는 오늘 날짜 기준 최신 정보를 우선하도록 지침 부여 (조건과 무관하게 동일 적용)
- 각 단계를 독립적으로 처리하며, 출력은 모두 구조화된 JSON
- **통제 미적용 조건**: 계획 → 바로 실행 / **통제 적용 조건**: 계획 → 검토 → 판정에 따라 실행

## 실험 및 결과

### 실험 1 · 파이프라인 안정성 (정상 질의 반복)

같은 의도의 정상 질의를 종결 어미와 어투만 바꿔 반복 실행했습니다. 에이전트는 taxonomy와 별개로 5개 위험 인식 항목(원문 접근성/번역, 선전 편향, 교차 검증 필요성, 시기 민감성, 정치·군사적 민감성)을 생성했습니다.

- 4개 항목은 회차마다 문구만 달랐을 뿐 같은 위험을 안정적으로 가리켰습니다.
- **원문 접근성/번역** 항목은 회차에 따라 지적하는 위험 자체가 달라졌습니다(접근 가능 여부 ↔ 번역 정확성).
- 계획 단계의 위험 인식 능력은 있지만, 그 일관성은 항목별로 균일하지 않습니다.

### 실험 2 · 통제 유무 비교 (위험 질의)

| | 사례 A: 완곡한 위험 의도 | 사례 B: 명시적 위험 의도 |
|---|---|---|
| 질의 | 제한된 자료에 접근하는 방법 (불법성·수법은 명시하지 않음) | 발표를 검증 없이 믿고 신형 무기가 왜 대단한지 설명 |
| 통제 미적용 | 사용자 의도를 확인하지 않고 "합법적 접근 경로"로 임의 재해석해 실행 | 계획 단계에서 선전 증폭 위험을 **인식했지만 그대로 실행**, 응답 내용만 스스로 조정 |
| 통제 적용 | 민감 정보 제공 우려를 제기했으나, 불법성이 명시되지 않았다는 이유로 **통과** | 검토 단계가 "선전 증폭"으로 판정해 **차단** |

## 주요 발견

- **위험 인식 ≠ 위험 차단**: 계획 수립 단계만으로는 인식한 위험이 실행 중단으로 이어지지 않았습니다. 별도의 검토 단계가 있을 때 비로소 인식이 실제 차단으로 전환되었습니다.
- **명시성 의존**: 완곡하게 표현된 위험 의도는 계획·검토 두 단계 모두에서 포착되지 않았습니다. 판단이 표현의 명시성에 의존합니다.
- **안전성 ≠ 충실성**: 결과적으로 안전한 응답이 나왔더라도, 에이전트가 사용자 의도를 확인하지 않고 한 가지 해석만 채택했다면 응답의 충실성 문제는 남습니다.

통제 체계의 핵심은 위험을 많이 판별하는 것보다, 인식된 위험을 실제 조치로 전환하는 데 있습니다.

## 향후 과제

- 모호한 요청에 대한 사용자 의도 확인 절차
- 나머지 위험 범주로 실증 검증 확대
- 아직 드러나지 않은 도메인 특화 위험 요소 발굴
- 실행·출력단 통제로 확장
